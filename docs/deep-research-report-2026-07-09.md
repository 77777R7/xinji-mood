# 心迹 Mood 深度研究 + 产品诊断完整报告（2026-07-09）

> 数据来源：105 个研究 agent 的市场深度调研（22 条结论经 3 票对抗核验通过）+ 竞品差评/周报设计/语音验证补充研究 + 本项目代码库完整分析。

## 一、需求验证：真实存在，但有一个致命前提

**结论：需求是真的，方向是对的，但这个品类的生死线不在需求端，在留存端。**

### 支持需求成立的证据（全部经过 3 票对抗核验）

- **付费意愿已验证**：Health & Fitness 类目（情绪类 app 所属类目）trial-to-paid 转化中位数 39.9%（top 10% 达 68.3%，RevenueCat 7.5 万 app 数据）；Adapty 独立数据给出周订阅带试用漏斗：9.5% 装机→试用、42.2% 试用→付费。该类目单装机 LTV $1.21，是所有类目最高。
- **AI 溢价存在**：AI 类 app 的单装机收入约为整体中位数的 2 倍（D60 $0.63 vs $0.31），但 RevenueCat 明确警告 "AI 本身不是差异化"，且 2026 年数据显示 AI app 流失快 30-36%、退款率高 20%。
- **VC 与市场信号**：Rosebud（最直接的英文竞品）2025 年 6 月拿了 Bessemer 领投的 $6M 种子轮，累计 5 亿字日记；付费墙锁的正是**长期记忆 + 语音**——这恰好就是你的核心 loop，说明市场领导者认为这两样是用户愿意付钱的东西。
- **中文市场已验证**：心光（Lifelight）CN App Store 4.8 星 / 1.3 万评分，¥18/月、¥98/年，苹果编辑推荐。中国心理咨询行业 2020 年已达 480 亿元规模。
- **学术确认了你要解决的痛点**：对 32 款商业情绪 app 的研究发现它们"支持记录和反思，但缺乏对准备和行动阶段的支持"（PMC5977660）；用户访谈研究发现"app 普遍不帮用户找相关性，把找模式的活留给用户自己"（PMC8387890）。

### 必须直面的风险数据

- **D30 用户留存约 3%**（区间 3-8.5%）；近 30% 年订阅在第一个月内取消；续费曲线从第 1 次续费 59.2% 衰减到第 5 次 27.6%；H&F 类目首次续费率约 30.3%，**是所有类目里最差的**。
- 该类目赢家通吃：top 10% 的 app 拿走 92.6% 的类目收入；只有约 5% 的 H&F app 前两年收入超过 $10K。
- 被证伪的数据：那个"数字日记市场 $5.69B、11.5% CAGR"的市场规模数字 0-3 被否决，不可引用。需求验证要靠漏斗数据和竞品 traction，不是 TAM 报告。

**给你的直接含义**：不要问"有没有人要这个"（有），要问"用户第 8 天为什么还打开它"。你所有的产品决策都应该围绕这一个问题。

## 二、竞品格局：你的位置比你想象的清楚

### 竞品速览

| 产品 | 核心 loop | AI | 定价 | 用户抱怨 |
|---|---|---|---|---|
| **Rosebud**（最直接） | 对话式 AI 日记 → 每周报告 | 长期记忆专利技术、CBT/IFS 框架、语音锁在付费档 | 免费 + $12.99/月 | AI 会"忘记"重要往事；回复 8-10 次后套路化；付费墙太狠 |
| **心光**（中文最直接） | 生活记录 + AI 陪伴 → 自我洞察报告 + 每周来信 + 语音交流 | 对话式陪伴型 | ¥18/月 ¥98/年 | 试用期只有 2-3 天；情绪评分公式曾出错；安卓版严重落后 |
| **Bearable**（身体模式最接近） | 记录因素+症状 → 相关性报告 | 无 LLM，纯统计（均值对比，无置信度） | $34.99/年 | "适合记录，**不适合洞察**"；相关性误导人；记录疲劳 |
| **Daylio** | 表情打卡 → 统计图表 | 无 | $35.99/年 | 高级统计看不懂（"confidence"没人理解）；语音输入是被点名要求的缺失功能 |
| **How We Feel** | Mood Meter 144 情绪词 → 当下调节策略 | 无 | 完全免费（非营利） | 几乎没有——它免费占死了"基础情绪打卡"这个地板 |
| **Finch** | 小行动 → 养宠物鸟 | 无洞察 | 免费 + $9.99/月 | D1/D7 留存 54%/37%，**超过 Duolingo** |
| **Mindsera** | 写作 → 50+ 思维模型分析 | 可全库问答但需用户主动问 | $14.99/月 | 只有思考框架，没有行动；仅英文 |

### 三个最重要的战略发现

1. **市场干净地裂成两半**：洞察无行动（Bearable、Daylio、Mindsera）vs 行动无洞察（Finch、Fabulous、Stoic）。**没有任何一家产品跑通「模式洞察 → 个性化微行动 → 追踪行动是否有效 → 反哺洞察」的闭环**——补充研究专门找了，找不到，这个"找不到"本身就是核验过的发现。这正是你 action-system-v1.md 里已经设计、且代码里已经部分实现的东西。
2. **"跨记录模式识别"没人做好**：Rosebud 是唯一因"发现了我自己没意识到的模式"被反复表扬的产品，但被记忆失效拖累；Bearable 有相关性但用户说误导；Daylio 有统计但没人看得懂。**主动推送、带证据、带置信度的 Pattern Card 是空位。**
3. **但入口不是空位**：Nuju 已经在做"30 秒打卡 + AI 解读 + 周报"；心光已有周报+语音+洞察报告。你赢不在"做了什么功能"，在**闭环执行质量**。另一个警示：心岛日记创始人做了近 10 年 NLP 情绪日记后放弃了纯日记模式，转向 AI 对话陪伴——纯记录模式已被中文市场的老兵证伪，你的"洞察→行动"方向恰好是对这个教训的回答。

### 差异化定位（一句话）

> 别人告诉你"你这周很焦虑"（描述），心迹告诉你"你的周日晚焦虑→浅睡→周一易怒这个循环出现了第 4 次，上次「10 分钟散步」对你有效，今晚要不要再试一次"（可干预的循环 + 被验证过的行动）。

## 三、你的项目现状：比你自己感觉的好，但断在关键处

代码分析总体判断：**`src/` 核心逻辑和 AI server 是真正契约驱动、有测试（166 条断言）、高质量的；你的迷茫不是因为方向错了，而是因为规格书里最核心的信任机制还没建出来，且 app 实际上是个"披着 React Native 外壳的 web app"。**

### 已经真实跑通的（不要推翻）

- 语音录制 → OpenAI 真实转写（`gpt-4o-mini-transcribe`）→ LLM 结构化 trace 提取（严格 JSON schema + 服务端消毒）
- **纵向 pattern 检测是本地规则引擎**：按 `context|body|thought` 归一化 key 分组，5 天窗口内 ≥3 次且跨 ≥2 天 → loop 可见，≥4 次 → 可行动（`dataFoundation.ts:952`）
- **行动学习子闭环已经闭合**：行动完成 → 帮助度记忆（helped×2、too_much=−2）→ 反哺下次推荐。这是全市场没人做的东西，你已经写出来了
- 周报两层架构（本地算 facts，LLM 只改写措辞）——这是**正确的**架构，比让 LLM 直接分析原始数据靠谱得多
- 安全分级（4 级，高危时禁卡片禁行动）符合"不让 LLM 决定支持性文案"的原则

### 断裂的地方（按严重度排序）

1. **Pattern 反馈闭环未实现**——规格书自己称之为核心信任机制（`mvp-data-contract.md:287-338`）：用户无法对 Pattern Card 说 "Feels right / Not quite"，模式被展示但用户永远无法作用于它。这是逻辑闭环最大的洞。
2. **web-only 的现实**：`MediaRecorder`、`localStorage`、`window` 全部只在 web 生效，native 端录音、持久化、TTS 全部静默失效。没有 expo-av/AsyncStorage。**你现在没有手机 app，只有网页。**
3. **第 4 个 tab（me/隐私/设置）是死按钮**（App.tsx:4138-4140）：`UserPrivacyState` 全部定义了但无法导出、删除、控制数据——而研究显示**隐私是这个品类的购买阻断因素**（心光最被表扬的就是本地优先）。
4. **8543 行的 App.tsx**，约 87 个 hooks 在一个组件里，规格书要求的 11 态 draft 状态机被非正式 step enum 替代，App.tsx 零测试。
5. 服务器不可部署：无鉴权、无限流、CORS `*`、客户端三处硬编码 `localhost:8084`；默认模型名 `gpt-5.4-mini` 疑似不存在的占位符。
6. 周报固定滚动 7 天窗口，老数据掉出周报但仍在 Patterns tab——两个界面会互相矛盾。
7. `did_not_help` 的主动降权规则（action-system-v1.md:503）没实现；Pattern Card 的"基于哪 N 条记录"证据链（`similarPastCheckInIds`）没有露出。

## 四、优化方案

### 4.1 整体框架优化（优先级排序）

**P0 — 先决定一件事：web 还是 native。** 建议：**近期承认它是 web app**（PWA 分发做冷启动验证），把 expo-av + AsyncStorage/SQLite 的 native 化作为验证后的里程碑。原因：你现在最缺的是留存数据，不是应用商店；而 native 化前必须先解决持久化和录音抽象层。

**P1 — 拆 App.tsx，但按"缝"拆不按行数拆**：把 4 个 screen + draft 状态机（实现规格书里的 `DRAFT_TRANSITIONS` reducer）拆出来即可，业务逻辑已经在 `src/` 里了，不需要引入重型状态库，一个 `useReducer` + context 就够。给 draft 状态机补契约测试。

**P2 — 服务端最小可部署化**：环境变量化 API 地址、加一个简单 bearer token、限流、把模型名改成真实存在的模型。统一双份安全关键词表（server:269 和 dataFoundation.ts:503 各一份，会漂移）——抽成共享 JSON 由两端引用。

**P3 — 隐私即卖点**：把 me tab 从死按钮变成真实的隐私面板（导出 JSON、一键删除、本地模式开关）。这不是杂务，是中文市场被验证的差异化点。

### 4.2 AI 框架优化

基本判断：**"本地规则做纵向、LLM 做单次提取和措辞"这个基本盘是对的，不要推翻它去做"把全部历史塞给 LLM 分析"**——Rosebud 的最大差评就是记忆失效和回复套路化，说明纯 LLM 纵向记忆并不可靠。需要的是定向增强：

1. **给 `/reflect` 加"薄记忆"**：不传全文，传**结构化摘要**——当前活跃的 loop 候选（key、次数、置信度）+ 最近 3 条 trace 的 chainKey + 行动帮助度记忆摘要。这让 AI 的即时回应能说出"这和你周二说的情况像"，解决"AI 很泛"的问题，而 token 成本只增加几百。
2. **防谄媚（anti-sycophancy）写进 system prompt**：用户明确反感 "yes-man" AI（arXiv 2601.10467 里用户自己写 "anti-glazing" 指令）。规则：先具体后共情、引用用户原话作为证据、不做无据断言。但注意校准——脆弱用户有时需要肯定，所以是"有证据的温暖"而不是冷酷。
3. **置信度必须说人话**：Daylio 的 confidence 没人看懂，Bearable 的相关性被骂误导。Pattern Card 应该是"过去 5 天里出现了 3 次，都在晚上"而不是"置信度 0.72"。在卡片上**主动承认不确定性**（"也可能是因为这几天都没睡好"）反而会建立信任。
4. **证据引用来自用户确认过的转写文本**：30 秒语音即使 10% 字错率也不毁"情绪大意"，但 Pattern Card 上引用的原话必须来自用户过目过的文本，否则"AI 听错了我的话"会造成信任伤害。中文 ASR 注意方言问题（微信语音转文字官方只支持普通话；讯飞声称支持 202 种方言）——转写后展示可一键修正，你已经有编辑功能，保住它。
5. **成本结构没问题**：单次提取 900 token 上限 + 周报 520 上限已经很克制。真正要加的是每用户每日调用配额（防滥用，也控成本）。

### 4.3 功能与逻辑闭环（核心）

完整闭环应该是五段，目前断了两处：

```
① check-in（已通）→ ② Pattern Card 生成（已通）→ ③ 用户确认模式（断！）
→ ④ 行动推荐+完成反馈（已通，市场独有）→ ⑤ 周报汇总并预告下周（半通）
```

#### Pattern Loop 怎么做（修复 ③）

- Loop 变为"可见"时（≥3 次），卡片下加两个按钮：**"是这样的" / "不太对"**。就这么简单开始，不要做三态五态。
- "是这样的" → 该 loop 的 confidence 加权、进入"已确认模式"列表、解锁行动推荐入口；"不太对" → 降权，且**追问一个单选**（"是场景不对/是感受不对/完全没有这回事"）反哺归一化 key。
- **已确认的 loop 要有生命周期**：活跃（近 5 天出现过）→ 沉睡（14 天未出现，周报里庆祝"这个循环两周没来了"）→ 复发（重新出现，温和提示"它回来了，上次 X 有帮助"）。**循环的消退就是你产品的成功指标**，让用户看见它。
- 露出证据链：点开卡片能看到"基于这 4 条记录"，每条附用户确认过的原话片段。这直接回应"Rosebud 记忆失效"的差评——你的证据是可核查的。
- **模式触发式提醒是你的科学蓝海**：习惯研究综述显示 54% 的干预只用定时提醒、仅 7% 测试过情境触发提醒（Zhu et al. 2024）。当系统检测到"周日晚循环"，就在周日 18:00 发一条**具体到模式的**提醒（"周日晚的那个循环最近出现过 3 次，今晚睡前要不要来 30 秒？"），而不是每天 21:00 的通用提醒。

#### Action 库怎么做

- **6 个不够，但不要变成 60 个**。Bearable 的教训是选项过载 → 记录疲劳。建议第一阶段 12-18 个，按已有的三层模型（Definition → Recommendation → Completion）扩展，每个 loop 类型（身体紧张/思维反刍/情绪低落/睡眠）配 3-4 个不同负担等级的行动。
- **全部改写成 if-then 格式（实施意图）**：这是行为科学里对心理健康人群效应量最大的干预形式（元分析 28 项研究 d≈0.99，Toli et al. 2016，即使打折校正后仍显著）。不是"多散步"，而是"**如果**明天下午又觉得胸口发紧，**就**离开工位走 5 分钟"。Pattern Card 恰好提供了 if 的部分——这是洞察和行动的天然接口，也是竞品做不到的（它们没有 pattern 做触发器）。
- **行为激活（BA）做骨架**：数字化 BA 对抑郁短中期有效（2/3/6 个月均显著，JMIR 2025 元分析）但 12 个月效应消失、对焦虑无显著效应——含义：action 库必须设计成**持续再触发**的（靠模式触发式提醒），而不是指望用户做一次就好；且对焦虑类 loop 主打的行动应偏身体调节（呼吸、着地技术，How We Feel 的路线）而非行为激活。
- **补上 `did_not_help` 主动降权**（规格书里写了没实现），并加"行动效果回访"：行动完成后的**下一次** check-in，如果同一 loop 没有复现，把功劳可视化——"上次散步之后，这个循环这周没再出现"。这一句话就是你的闭环时刻（loop-closing moment），全市场没有人做这个。
- 谦逊归因：单次行动≠因果。措辞永远是"可能有帮助"，累计 3 次正反馈后才升级为"对你通常有效"。

#### Weekly Reflection 怎么做（设计原则来自 Wrapped/Whoop/Oura/Strava/Rosebud 案例研究）

1. **章节化叙事，不是仪表盘**——Reflectly 的死因就是"只有日志没有为什么"。结构建议：`这周的天气（总体基调）→ 出现的循环（哪个来了几次）→ 你做了什么（行动及其效果）→ 变化（对比你自己的前 3 周基线）→ 下周的一个 if-then`。5-7 张可滑动卡片，不要长文。
2. **只和自己比**（Whoop 的滚动 3 周基线、Oura 的"进步最大项"），情绪数据**永远不做用户间比较**——学 Gentler Streak 的"温暖非竞争"，不学 Wrapped 的排名。
3. **身份化措辞但不贴标签**：不是"你是焦虑型人格"，而是"这周的你，在压力下更早察觉到了身体信号"。
4. **数据门槛做成钩子**：≥3 次 check-in 解锁完整周报（Whoop 要 5 天、Rosebud 要 1500 字/周才给深度报告）——把周报变成每日打卡的动机，直接攻击 D30 留存问题。
5. **为稀疏数据设计**（Strava 的约束：3 次活动的用户和 366 次的都要被庆祝）：只打卡 1 次的那周，周报就写那一次，绝不显示空表格。
6. 固定节律 + 可配置：默认周日晚推送（无 A/B 证据证明周日最优，但固定节律本身有据；Whoop 用周一早），允许用户改。
7. **加"人物志"**：Rosebud 的 Cast of Characters（本周在你记录里出现的人）是被验证的惊喜点，且天然适合中文语境。
8. 每份周报配**一张**隐私安全的可分享卡（只有意象和基调，无敏感内容）。
9. **循环消退要在周报里庆典化**："那个周日晚的循环，已经 2 周没有出现了"——这是你独有的、竞品给不了的高光时刻。
10. 修 bug：周报窗口和 Patterns tab 的时间口径要统一（按自然周 + 明确周起始日，而不是滚动 7 天）。

## 五、行动优先级（如果只做五件事）

1. **实现 Pattern 反馈按钮 + 循环生命周期**（补上闭环最大的洞，规格书都写好了）

## 六、关于迷茫

**你不需要换方向，你需要把已经设计好的闭环走完。** 需求真实、付费意愿有数据、你选的"洞察→行动→验证"闭环恰好是被学术确认的品类缺陷和被竞品空置的位置，而你的 `src/` 核心已经实现了一半（行动学习记忆这块甚至领先所有竞品）。真正的敌人只有一个：D30 留存 3% 的品类地心引力。所有资源都应该投向"用户第二周为什么还回来"——模式确认、行动生效的可见证据、和一份值得等待的周报，就是你的三个回答。
